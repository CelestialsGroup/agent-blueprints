## HTTP/1.1 与 framing 设计

### 路由和请求目标

- 只接受精确 `POST /v1/runs`；不接受 trailing slash、query、absolute-form、authority-form、
  asterisk-form、redirect 或路径 normalization。
- 只接受 `HTTP/1.1`。
- 必须恰有一个语法有效且与 loopback component listener 匹配的 `Host`；重复、逗号合并、
  userinfo、空 host、非法 port、外部 authority 或借 Host 替换 Audience 全部 `400` 并关闭连接。
- `Expect` 不进入隐式 `100-continue` 路径；本切片对任何 `Expect` fail closed 并关闭连接。

### Header 与 body framing

- 必须恰有一个 `Content-Type`，值精确为 `application/json`；不接受参数、大小写替代、
  合并值或重复 header。
- 必须恰有一个十进制 `Content-Length`；只接受 ASCII digits 的规范非负形式，拒绝符号、
  OWS 内嵌、逗号列表、重复值、前导歧义、越界整数和缺失长度。
- 任何 `Transfer-Encoding`，包括 `chunked`、identity、重复/组合编码，都在读取 body 前
  `400`；`Transfer-Encoding` 与 `Content-Length` 并存同样拒绝。
- framing、认证或其他 pre-body 检查失败时不尝试 drain 不可信 body，发送有界错误后关闭
  连接；若无法安全发送则直接关闭。

### 8 MiB pre-parse 上限和读取状态机

Contract `x-max-encoded-body-bytes=8388608` 是 wire-encoded body 上限：

1. `Content-Length > 8388608` 时，在 body read、Strict I-JSON、Schema、JWS 和任何 SQLite
   访问前立即返回 `413` 并关闭连接。
2. `Content-Length <= 8388608` 时只预分配有界缓冲，并按剩余字节精确读取；不得无界
   `read()`、不得等 EOF 决定 body 边界。
3. 使用总 read deadline，而不是每收到少量数据就无限续期。slow body 超过预算时关闭连接；
   能安全发送时输出 `400 StandardError`，否则只关闭，不伪造响应。
4. EOF/half-close 导致 short read 时，禁止进入 JSON/Schema/JWS/store；能发送时 `400`，
   否则关闭。
5. 精确读满后不消费属于下一 request 的字节；连接复用必须继续受既有 request-count、
   idle/read/write timeout 和响应上限控制。
6. 测试必须用 store spy 或只读 SQLite 快照证明超限、短读、slow body、timeout 和所有
   pre-admission 失败均为零事实。

## mTLS、Bearer 与不可替换绑定

- TLS 层继续使用 a1.1.1 已验证的 required client certificate 和精确 SAN URI allowlist；
  HTTP handler 只接收 process server 已映射出的唯一 `token_subject`。
- `Authorization` 必须恰有一个，scheme 精确为 `Bearer`，credential 是一个 bounded
  compact JWS；拒绝缺失、空值、重复 header、逗号合并、多 credential、控制字符、额外
  OWS/字段和超过现有 `max_token_bytes` 的 token。
- 不在 HTTP 层解码后信任 claims，也不记录 token；把原始 bounded compact JWS 和唯一
  mTLS `authenticated_caller` 交给 `SecureAdmissionCore.start`。
- core 必须继续验证签名、`iss=agent-platform`、配置 Audience、mTLS subject、
  `operation=start`、Contract/Profile/request digest、ProviderRevision、RuntimeRun/
  InvocationAttempt/Fencing 及时间窗。
- Host、body、query、traceparent 或自定义 header 都不能提供或覆盖 Audience、operation、
  subject、request digest。mTLS identity 与 token `sub` 不精确相等时为 `401`，且发生在
  store 访问前。
- token/body/private key/public-key PEM、证书原文和内部验证异常不得进入响应、日志或
  evidence；evidence 只允许非秘密 public-key/certificate fingerprint。

## 成功响应

将 `RuntimeStatus` 显式映射为 Contract `AgentRuntimeRunStatus` document，不对 dataclass
做通用反射或泄露私有字段：

- 映射锁定 Schema 所需的 identity、status、sequence、fencing 和 timestamp；
- 仅在存在且 Contract 允许时映射 checkpoint、completed/result/error 字段；
- `cancellation_evidence_reference` 等 Provider-private 字段不得直接外泄；
- 在序列化和写 socket 前用锁定
  `urn:agent-platform:agent-runtime-run-status:v1` Schema 验证；
- 使用确定性、有界 JSON 编码，检查 encoded response 不超过配置的
  `max_response_bytes`；
- 合法首次 Start 和合法幂等 replay 均返回 `202`、精确
  `Content-Type: application/json`、正确 `Content-Length` 和连接策略。

若 transaction 已提交但 response validation/encoding/write 失败，不回滚或补写事实；
连接关闭后，caller 必须用相同 idempotency key、相同 digest 和 fresh JTI 重试并得到完全
相同的 RuntimeRun document。

## 封闭错误映射

所有能发送的错误响应必须先构造固定 code/message/retryable/fresh trace ID，再通过锁定
`urn:agent-platform:standard-error:v1` Schema 验证。不得把异常字符串、token、body、
private key、SQL、路径或 traceback 放入 `message/details/violations`。

| HTTP | 仅允许的 Start 分类 | retryable / header |
|---|---|---|
| 400 | request target、Host、Content-Type、Content-Length、Transfer-Encoding/Expect、short read，以及 Strict I-JSON、Schema、digest、普通请求语义失败 | `false` |
| 401 | Bearer 缺失/格式、JWS header/signature/claims、issuer、audience、mTLS subject、operation、token request binding/time-window 失败 | `false` |
| 403 | 已认证 workload 或 durable authorization/security binding 不被允许 | `false` |
| 409 | mutation JTI replay、idempotency digest conflict、RuntimeRun immutable identity conflict | `false` |
| 413 | `Content-Length > 8388608` 的 pre-parse encoded-body overflow | `false` |
| 422 | 当前 ProviderRevision 不支持的 sandbox/checkpoint/restore 语义 | `false` |
| 429 | 已通过 mTLS 且路由/请求可归类为精确 Start 后的并发容量耗尽 | `true`，正整数 `Retry-After` |
| 500 | 未预期内部错误或非 transient SQLite error | `false` |
| 503 | draining/not-ready 或 SQLite busy/locked | `true`，正整数 `Retry-After` |

映射实现使用 closed dispatch，新增异常类型必须显式分类并有测试；不能落入把所有异常
字符串直接返回的 catch-all。连接已丢失时只关闭，不声称已发送某个 HTTP 状态。

## 停止条件与权威缺口

以下任一条件出现时立即停止受影响范围，并在本文台账记录：

- HEAD、工作树或任何锁定 Blueprint/Contract/Manifest/Suite/projection digest 与批准基线
  不符且无用户授权；
- 必须新增第三方依赖；
- 必须修改 Blueprint 或 Contract 才能得到目标行为；
- Host、framing、Bearer、body limit、Schema/JWS/caller binding 中任一必要验证无法在首次
  store 访问前完成；
- 某个 HTTP 状态映射没有锁定 Contract 权威；尤其不得解决 Status/Event 400 歧义；
- 必须引入生产 composition root、Go adapter、ProviderResolution、token issuer/private-key
  custody、平台 PostgreSQL/Temporal caller、CanonicalEvent 或生产 Safety Controller；
- 测试只能用 mock 冒充所声明的 TLS、installed-wheel subprocess、SQLite transaction 或
  response-loss 行为；
- response 不能通过锁定 AgentRuntimeRunStatus、错误不能通过 StandardError，或需要泄露
  内部信息才能调试协议；
- 无法维持 mutation JTI/accepted fact 原子性、同 digest replay 或 digest conflict 语义；
- 完整 `make validate-implementation` 任一既有 Gate 回归且不能在本切片边界内修复。

当前权威缺口保持不变：生产 caller/token issuance/Provider resolution、Platform Runtime
authority、CanonicalEvent、Safety Controller、Status/Event 400 解释和 a1.1.3 recovery
都不由本切片闭合。
