## 下一切片判断与顺序依赖

只读权威和代码审计确认：B03.2a2.0 已闭合 framework-neutral 五操作 Go Port、稳定 opaque
values、封闭 read failure/mutation outcome 和 fresh-read/no-retry reconciliation requirement；
当前没有 HTTP adapter。后续三个候选的依赖顺序不能交换：

1. a2.1 必须先提供严格、未生产接线的五操作 HTTP adapter；
2. a2.2 才能用该 adapter 调用真实 installed Native Runtime，形成跨语言 mTLS/HTTP/SQLite
   process evidence；
3. a2.3 最后动态读取锁定 Suite，绑定 a0-a2.2 的分层证据并保持平台 case 不提升。

a2.1 不再拆成只覆盖部分操作的对外子切片。Capabilities、Start、Status、Command、Events
共同实现现有 `AgentRuntimeProvider`，部分 adapter 不能独立满足 Port，也会制造临时接口或
重复 transport policy。本文仍按 validator/config、read、mutation、evidence、最终 Gate 分阶段
实施，以便每阶段独立验收和回滚。

本切片能独立闭合，因为 endpoint HTTPS origin、TLS trust/client identity、Contract Schema
closure 和 invocation token 全部由 component/integration harness 以不可变依赖注入；adapter
不解析 ProviderResolution，不签发 token，不持有 private key，不注册生产 endpoint，也不创建
生产 caller、父事实或 composition root。若严格行为必须依赖这些缺失 authority，立即停止受
影响范围，不以测试影子事实或默认系统 trust 绕过。

锁定 OpenAPI 与 B03.2 总计划还存在两项 transport authority gap：

- Status/Event responses 未声明 HTTP 400；adapter 不把 read 400 映射成合法 request failure，
  只能作为 `invalid_response`；
- B03.2 总计划的分类表提到 read 429，但锁定 OpenAPI 的 Capabilities/Status/Event responses
  均未声明 429；adapter 不接受或重试 read 429，继续以 `invalid_response` fail closed。

这两项 gap 不阻塞 OpenAPI 已声明响应及 mutation 429 的实现，但必须进入最终 evidence 的
machine-readable blocked 列表。

## Scope

本切片只实现和证明：

- 新增 `internal/runtimeport/httpadapter`，完整实现现有五操作 `AgentRuntimeProvider`；
- 构造时只接受精确 HTTPS origin、已配置 Root CA/client certificate/TLS >= 1.2 的 injected
  `http.Client`、显式连接/handshake/header/operation/response byte bounds 和 required Contract
  validator；禁止环境变量、默认系统 trust、proxy、redirect 或生产注册；
- 每次操作最多一次 adapter dispatch；禁用 redirect、compression、keep-alive transport retry
  条件，Start/Command 不提供 retry loop、callback、attempt count 或隐式第二次请求；
- Capabilities 使用精确 `GET /v1/capabilities`、无 bearer，验证 locked Schema、expected
  ProviderRevision 和 canonical document immutability；
- Status/Event 使用 exact path、canonical decimal query、single bounded Bearer；Event 省略值不在
  adapter 内猜测，Port request 已携带归一化后的 `after_event_sequence`/`limit`；
- Start/Command 在 dispatch 前通过 required validator 验证完整 Schema、duplicate/UTF-8/JSON
  bounds、body identity、fencing、request digest 与 Invocation binding；原 opaque bytes 不进入日志；
- success 只接受 OpenAPI 精确 status、HTTP/1.1、单一 `application/json`、canonical
  `Content-Length`、无 `Transfer-Encoding`/`Content-Encoding`、bounded complete body；
- 使用锁定 Schema validator 后再映射 generated transport DTO 到稳定 Port values；验证
  runtime identity、fencing、Event runtime identity/order/cursor 和 admitted Registry payload；
- StandardError 先通过锁定 Schema，再只保留 closed failure class、code 和 bounded details；
  不根据 `retryable` 文本提升已知性；
- mutation 仅在明确 202 成功时 `accepted`；声明的 4xx/429 为 known `rejected`；本地 pre-dispatch
  failure 为 `not_dispatched`；一旦进入 `Client.Do` 后的 timeout/reset/invalid/truncated/unexpected
  response 及 500/503 全部为 `outcome_unknown`，且携带 a2.0 fresh-read/no-retry requirement；
- focused normal/Race tests 使用真实 loopback TLS/HTTP sockets 和锁定 Contract closure；受控 Go
  peer 只证明 adapter transport，不冒充 installed Python/process/SQLite evidence；
- 独立动态 evidence、source manifest、敏感扫描、供应链和完整 Application Gate。

## 全阶段不变量

1. Blueprint/Contract zero-diff；不得修改权威迁就实现。
2. 只使用 Go 标准库和已锁定 Application dependencies；不得新增/升级依赖、生成 DTO 或 raw
   Contract copy。
3. root `runtimeport` 保持 framework-neutral；`net/http` 和 generated DTO 只进入 adapter package。
4. adapter constructor 不读取环境变量、文件、ProviderResolution、数据库或 Temporal；只有 harness
   显式构造。
5. injected client 必须显式 TLS trust/client identity；adapter 不持有 private key bytes、不签发 token、
   不允许 proxy/default trust/redirect。
6. Start/Command dispatch 代码路径只有一次 `Client.Do`；一旦进入 Do，任何无法证明的结果都不能
   降级为 not_dispatched/rejected。
7. read 不自动重试；400/429 不越过 OpenAPI 映射为合法 read failure。
8. response 必须在解析前受 byte/header/framing/content-type bounds；Schema validation 先于 DTO mapping。
9. token/body/StandardError message/raw transport error/checkpoint content/private key/traceback 不进入
   String、日志或 evidence；对外 failure 只保留 code、closed class 和 bounded details。
10. Provider Event 只作为 Provider-local Event；adapter 不创建 CanonicalEvent。
11. 每阶段先回填本文，再向总控任务报告；不暂存、不提交、不推送。

## Rollback、Data Retention 与 Forward-Only 边界

- a2.1 只新增 Go adapter/validator source/tests、evidence generator/Gate block 和文档；未生产接线时
  可整体移除这些未提交变更回滚。
- 本切片不创建 migration，不读写 Provider-local SQLite、Platform PostgreSQL、Temporal History、
  Event、checkpoint、JTI、InvocationAttempt 或 ReconciliationCase。
- token/request/response bytes 只在单次进程内调用和测试临时内存存在；adapter 不缓存 token/body；
  Capabilities cache 只保存 canonical SHA-256 和非秘密 provider identity。
- real loopback TLS tests 的 CA/cert/private keys、sockets 和临时文件仅在测试内生成并销毁；evidence
  不保留 private key 或完整证书载荷，只保留固定 marker/count/digest。
- ignored build/evidence 可重建或移除，但删除 evidence 不等于 durable rollback；再生成必须重新绑定
  source/log digest。
- 现有 SQLite v2、Event retention、checkpoint references、PostgreSQL/Temporal facts 和 committed
  evidence 的 forward-only 边界保持不变；a2.1 rollback 不触碰或重解释它们。
- 一旦未来 production wiring 获批，adapter rollback 必须单独证明已准入 wire/error compatibility；
  本计划不授权该 activation。
