## Scope

- Reproducible disposable PostgreSQL integration harness independent of a
  developer-installed database.
- SQL-first bootstrap migration with separate NOLOGIN Migrator and Application
  group roles.
- Minimal Tenant and ClientApplication ownership tables, constraints, explicit
  `tenant_id`, enabled and forced RLS, and least-privilege Application ACLs.
- pgx transaction runner that installs TenantContext transaction-locally and
  rejects missing context and nested transactions.
- Minimal sqlc-backed ClientApplication repository returning domain values.
- Real-database evidence for migration behavior, role separation, fail-closed
  TenantContext, cross-tenant isolation, and connection-pool reuse.
- Integration with the existing formatting, static analysis, generation,
  reproducible build, SBOM, provenance, and traceability Gate.

## Database Topology Decision

PostgreSQL roles are cluster-global. The fixed group roles are bound by comment
to the first bootstrapped Agent database name, and bootstrap rejects a second
Agent database name in the same cluster before creating Agent schema objects.
The accepted B02.1 deployment topology is therefore one Agent database name per
PostgreSQL cluster. Supporting multiple Agent databases in one cluster requires
a separate reviewed role-naming and provisioning design before deployment.

## Upgrade And Rollback

The bootstrap Down migration is intentionally forward-only because dropping
cluster roles, ownership, tables, or grants cannot be inferred safe. A failed
Down must leave migration version 1 and all objects intact; correction uses a
new reviewed forward migration.

Dependency or tool rollback restores the previous exact version and digest,
regenerates sqlc output where applicable, and reruns the full real-PostgreSQL
Gate. PostgreSQL data directories are never downgraded in place; recovery uses
a verified backup restored into an admitted image.

## Review And Completion Evidence

Reviewers verify:

- the migration DDL, object ownership, exact ACLs, RLS positive and negative
  behavior, and forward-only rollback classification;
- transaction-local TenantContext and the absence of session TenantContext;
- repository atomicity, domain-only return values, and conflict behavior;
- empty-database migration, Migrator Login, cross-tenant, privilege, rollback,
  and pool-reuse tests against real PostgreSQL;
- sqlc generation consistency, gofmt, `go vet`, locked Staticcheck, normal and
  race tests, reproducible artifacts, SBOM, provenance, and dependency lock;
- generated evidence under ignored `build/evidence/b02.1/`, followed by cleanup
  of reproducible build and cache output before staging.

## Unproven Boundaries

B02.1 does not prove full Phase 0B persistence, an end-to-end product path,
multi-cluster operations, scale or SLOs, backup restoration, disaster recovery,
formal Contract freeze, security approval, or production readiness. Those
claims require later slices and separately bound runtime evidence.
