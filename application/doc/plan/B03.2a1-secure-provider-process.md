## 审计结论

- a0 的 JSON 解码只拒绝重复键和非有限数，尚未拒绝非 UTF-8/BOM、单独
  surrogate、各种词法形式的非安全整数，也没有 Number token、指数、深度和节点上限。
- a1.0 基线的 `NativeRuntimeKernel.open()` 自动迁移；a1.1 的 `serve` 必须改为只检查
  当前 Schema，绝不能隐式迁移。
- Command、Status 和 Event 当前先按 `runtime_run_id` 读取 Provider-local security
  binding，再完成 JWS 签名验证。虽然最终状态或事件读取仍在授权事务内，但无效签名
  可以通过 `not found` 与 token rejection 的差异探测 RuntimeRun 是否存在，也不满足
  OpenAPI 要求的“claims 在任何状态读取前匹配请求或认证路径”。开放 HTTP 路由前必须
  把 token 验证拆成 pre-store cryptographic admission 与 transaction-bound durable
  binding 两阶段。
- a0 未保存 Policy、Budget、Permissions 摘要和 RuntimeAuthorization 时间窗；a1.0
  已新增闭合安全绑定，并在同一只读事务中先核对绑定再暴露状态或事件，但其事务前的
  security-binding lookup 仍早于签名验证，必须由 a1.1.0 关闭存在性 oracle。
- 已有 data-bearing a0 store 没有权威数据可以回填上述绑定。升级必须 fail closed，
  不能填 `NULL`、空字符串、伪摘要或测试影子事实；仅空 store 可执行 Up/Down。
- Runtime Schema 继续从校验过的只读 Contract root 与已提交 projection manifest
  加载。wheel 不复制原始 Contract Schema，也不在 generated TypedDict 上虚构完整
  Draft 2020-12/语义验证能力。
- 依赖锁已经包含并审计 `cryptography==49.0.0`、`PyJWT==2.13.0`、
  `jsonschema==4.26.0`、`rfc8785==0.1.4`。a1 不增加 Web Server 或 JOSE 依赖。
- Cancel、Pause、Resume、Checkpoint 是
  `/v1/runs/{runtime_run_id}/commands` 的 Command 变体，不新增私有路由。

## 切片决定

### B03.2a1.0 Secure Admission Core

第一个可实施切片只建立可由未来 mTLS Handler 调用的安全准入核心：

- 不可变安全配置与公开验证密钥集合；
- 锁定 Contract Schema 加载和摘要校验；
- 有界 Strict I-JSON 原始字节解析；
- Start、Command、Status descriptor、Event descriptor、JWS Header 与 Claims 的
  Draft 2020-12 验证；
- 完整请求/自摘要重算和当前可由呈现文档证明的语义闭合；
- EdDSA/ES256 Header、Claims、签名、Audience、Operation、Scope、时间、JTI、
  Caller Subject 与 Fencing 绑定；
- Provider-local 安全绑定持久化、原子 mutation JTI 消费、授权后的 Status/Event 读取；
- 独立单元/组件证据、依赖审计和逐个 locked Suite case 的精确 verdict/boundary。

a1.0 不声明 HTTP、TLS、mTLS 或真实进程行为已实现。

### B03.2a1.1 mTLS Provider Process

a1.1 仍然过大，必须拆成以下可独立提交、测试和回滚的子切片。每个子切片都保持完整

| B03.2a1.1.1 mTLS Process Foundation | immutable config、migrate/serve CLI、bounded stdlib HTTP/TLS、PKI、Capabilities、readiness/drain | installed-wheel 真实 subprocess TLS/lifecycle 证据 |
| B03.2a1.1.2 Start HTTP Boundary | Start framing、8 MiB pre-parse 413、a1.0 接线、202/StandardError、响应丢失恢复 | Start 正负向 HTTP 与 commit 前后 crash 证据 |

#### B03.2a1.1.0 Pre-Transport Safety Preconditions

首个子切片不监听网络、不解析证书，也不声明 HTTP/TLS/mTLS 已实现。它只关闭未来
`serve` 暴露前的两个必要安全前提：

1. `migrate` 是唯一允许执行 DDL 和首次绑定 immutable Runtime/Security metadata 的
   路径；`open_current` 只读验证精确连续 migration version/name/digest 和既有 metadata；
2. 缺库、旧版、未知高版本、断档、digest drift 或 metadata 缺失全部 fail closed，
   check-current 不创建数据库、表、migration row 或配置 row；
3. 测试和未来 CLI 必须显式选择 migrate 或 open-current，不保留可被 `serve` 误用的
   自动迁移入口；
4. Runtime token 先完成 bounded compact JWS、Header/Claims Schema、签名、时间、
   issuer、audience、caller subject、operation、Contract/Profile 和请求派生字段验证，
   再进入同一事务核对 Tenant、Run、Manifest、Authorization、Policy、Budget、Permission
   与 Fencing 等 durable binding；
5. Command、Status、Event 对无效签名、错误 typ/kid/alg/sub/aud 必须在首次 store 调用前
   失败；存在和不存在的 RuntimeRun 不得形成 404 oracle；
6. mutation JTI 与接受事实原子提交、Status/Event 同事务授权读取、全部 a1.0 正负向行为
   保持不变。

a1.1.0 的 crash matrix 覆盖 migration commit 前、Schema commit 后 metadata 绑定前、
metadata commit 前，以及 cryptographic admission 后 durable transaction 前。重开后只能
看到完整旧状态或可幂等继续的新状态，不能出现部分 migration、部分 configuration 或
消费但无事实的 JTI。该子切片不新增 SQLite migration 或第三方依赖；回滚为代码级回滚，
data-bearing v2 store 仍保持 forward-only。

以下任一情况停止 a1.1.0：锁定输入变化；无法在 store read 前验证 token 签名和请求派生
绑定；check-current 需要写数据库；需要修改 Contract；或只能通过放宽 NotFound/Forbidden
防枚举规则保持现有 API。

#### B03.2a1.1.1-B03.2a1.1.4 Process And Transport Scope

后续子切片按顺序实现：

- 明确的 `migrate` 与 `serve` 入口；`serve` 只检查最新 Schema，禁止自动迁移；
- 有界 Python 标准库 HTTP/1.1 + TLS 组件服务器，不据此选择生产服务器；
- 测试 CA、Server/Client certificates、调用方证书身份到 `sub` 的确定性映射；
- readiness、drain、连接/请求/响应/并发上限和信号处理；
- OpenAPI 定义的 Capabilities、Start、Status、Command、Event 路由；
- 严格 `Content-Type: application/json`、encoded-body pre-parse limit、禁止 redirect
  与 Host/Audience 替换；
- 只输出 Contract `StandardError`，不泄露 token、请求正文、checkpoint 内容、
  private key 或内部异常；
- 真实 subprocess 终止、响应丢失、提交前后崩溃、SQLite 重开和恢复测试。

Status/Event 的 OpenAPI 响应没有列出 HTTP 400，但 B03.2 总计划把无效读请求分类为
400。a1.1.4 在权威解释明确前不得猜测或静默映射；受影响的 transport case 保持
machine-readable `blocked`，不影响其他子切片的 bounded completion。

## a1.0 详细设计与执行顺序

### 1. 不可变配置和 Contract 装载

新增 frozen 配置值，至少绑定 ProviderRevision、Runtime revision、Provider Audience、
允许的 caller subjects、`kid -> algorithm + public key`、最大 token bytes、clock skew、
Strict JSON depth/node/number-token bounds、Contract root、Manifest/Suite 摘要。

配置构造时拒绝重复 `kid`、算法/曲线不匹配、private key、空 caller、过宽时钟偏差、
文件系统根目录和与 durable kernel 不一致的 Provider/Audience。配置摘要只包含稳定、
非秘密值与 public-key fingerprint；不得记录 bearer token 或私钥。

Schema loader 必须：

1. 验证 `dependency-lock.json` 与 projection manifest 的版本/输入摘要；
2. 从只读 Contract root 加载 manifest 列出的完整 Schema closure；
3. 拒绝路径逃逸、重复 `$id`、缺失文件、文件摘要不一致和 closure 外 `$ref`；
4. 预编译 Start、Command、Status/Event descriptors、JWS Header/Claims 验证器；
5. 启动后不重载配置、Schema 或密钥。

### 2. 有界 Strict I-JSON

在 `json.loads` 和 JCS 前对原始 bytes fail closed：

- encoded bytes 只接受严格 UTF-8，拒绝 UTF-8 BOM、非法编码和单独 surrogate；
- 拒绝重复 object member、NaN、Infinity；
- 在 `int`/`Decimal` 大对象分配前限制 Number token 最长 1024 bytes、十进制指数
  绝对值不超过 400；
- 用十进制 coefficient/scale 的有界精确判定拒绝数学值为整数且绝对值超过
  `2^53-1` 的 token，包括 `.0` 和指数形式；非整数仍交由有限 IEEE-754/JCS 表示；
- 解析后迭代检查字符串无 surrogate，并限制最大 nesting depth 和总 value/member
  node 数；
- 运行 Contract 全部 5 个 JCS、3 个 Strict-valid、10 个 Strict-invalid 向量，
  不允许 skip/documented-only。

Start/Command 的 HTTP encoded-body limit 属于 a1.1；a1.0 的字节准入 API仍接收显式
上限并在解析前拒绝，供未来 Handler 无损调用。

### 3. Schema 与语义准入

顺序固定为：原始字节限制 -> Strict I-JSON -> Schema -> 自摘要 -> 跨字段语义 ->
JWS/Caller -> durable transaction。任何失败不得消费 JTI、创建 RuntimeRun、Command、
Event 或 execution work。

Start 必须至少证明：

- `request_digest` 等于移除该字段后的 RFC 8785 JCS SHA-256；
- RuntimeAuthorization、ExecutionBudget、AgentRunBudgetAllocation、PolicyDecision、
  EffectivePermissions 和每个 ArtifactGrant 的自摘要正确；
- Tenant、WorkOrder、RuntimeRun、AgentRun、RunManifest、ExecutionScope、
  InvocationAttempt、CommercialAuthorization、Budget、Policy、Permissions 交叉绑定闭合；
- Authorization/Policy/Budget/Grant/CommercialAuthorization 的 issued/not-before/
  expiry 窗口闭合，Authorization 未过期且不越过 Start deadline；
- `policy_decision.outcome == allow`，ArtifactGrant 不授予 finalize，
  `sandbox_bindings=[]` 且本 revision 的 sandbox permissions 为空；
- request 中的 authorization digest 与嵌入文档、token claims 完全相同。

只验证请求中呈现事实的内部一致性。a1.0 不能证明它们来自生产 RunManifest、
ProviderResolution、Token Issuer、Platform Database 或 Temporal caller。

Command 必须验证完整 Schema、移除 `command_digest` 后的摘要、Path/Body/Token
RuntimeRun、InvocationAttempt、Fencing 和 authority source。仅支持 a0 已实现的
Pause/Resume/Cancel/Checkpoint；其余 Contract 合法命令返回明确 unsupported，不能
绕过 Schema 或创建部分事实。

Status/Event 从 Path、Token 与应用 OpenAPI 默认值后的 Query 合成正式 descriptor，
按 `rfc8785-full-document-v1` 重算摘要；不接受 caller 提供的替代 descriptor。

### 4. JWS 和授权绑定

验证器按预期操作预先选择唯一 Runtime Invocation profile，不根据不受信任的 `typ`
动态选择。处理顺序为：

1. 对 compact JWS 总字节和三段长度设上限；严格 base64url 解码；
2. Header 经过 Strict I-JSON 和锁定 Header Schema；只允许 `EdDSA`/`ES256`、
   已配置 `kid`、精确 `typ=agent-runtime-invocation+jwt`，拒绝额外 Header；
3. `kid` 的配置算法必须与 Header 一致；Ed25519 与 P-256 key type/curve 必须匹配；
4. 验证签名后，Claims 再经过 Strict I-JSON 和锁定 Claims Schema；
5. 精确验证 `iss=agent-platform`、Audience、`sub=authenticated_caller`、
   ProviderRevision、Operation/Contract/Profile/Digest 和全部 scope/immutable digests；
6. 验证 `iat <= nbf < exp`、TTL 不超过 300 秒、允许的有界 skew，以及 execution
   Token 不早于或越过 RuntimeAuthorization/Policy/Grant/operation deadline；
7. Start 只允许 execution；Status/Event 只允许 safety_control；safety_control Command
   只允许精确 Pause/Cancel 且不继承执行或 Artifact 副作用权限；
8. Mutation JTI 与接受事实在同一个 SQLite write transaction 消费。失败和冲突不消费；
   read JTI 不创建 mutation replay 权威。

测试只生成临时 Ed25519/P-256 private keys。实现配置、store、日志和 evidence 只持有
public keys/fingerprints，不实现 issuer、private-key custody、rotation authority 或 revocation。

### 5. Provider-local 安全绑定与迁移

新增 SQLite v2 Up/Down migration，包含 immutable security configuration metadata 与
每个 RuntimeRun 的闭合安全绑定：Tenant、WorkOrder、WorkflowRun、AgentRun、
RunManifest、RuntimeAuthorization、Policy、Budget、Permissions、Authorization 时间窗和
当前已观察 Fencing。Start 在创建 RuntimeRun 的同一事务插入绑定；Command 在写事务中
先核对绑定；Status/Event 在同一只读事务中先核对 token/descriptor 绑定再读取事实。

升级规则：

- 空 v1 store 可以 Up 到 v2，也可以在仍为空时 Down；
- v1 store 一旦存在 RuntimeRun/JTI/Command/Event/Checkpoint/Work 数据，v2 Up 失败；
- v2 data-bearing store forward-only；不删除、回填或解释旧事实；
- migration digest 漂移、未知更高版本、缺少连续版本均启动失败。

a1.1 再把库级 migrate/check-current 能力暴露为独立进程命令，并从 `serve` 移除
自动迁移。

### 6. a1.0 测试和证据

测试至少覆盖：

1. 全部锁定 JCS/Strict I-JSON 向量，以及 BOM、非法 UTF-8、depth/node/number-token
   边界和超界失败；
2. Schema closure 摘要、未知字段、错误类型/格式、缺失条件字段；
3. Start/Command/Authorization/Policy/Budget/Permissions/Grant 摘要正反例；
4. EdDSA 与 ES256 成功；wrong typ/alg/kid/key/aud/caller/op/contract/profile/digest、
   签名篡改、额外 Header/Claim 全部拒绝；
5. expired/not-yet-valid/over-300s、早于 Authorization/Policy/Grant、晚于
   Authorization/Policy/Budget/CommercialAuthorization/Grant/deadline；
6. Start、Command、Status、Event 的 Path/Body/Query/Invocation/Fencing/scope 替换拒绝；
7. mutation JTI 成功原子消费，Schema/token/digest/语义/冲突失败不消费；
8. 未授权 Status/Event 在读取 Runtime 状态前失败；授权读与绑定核对发生在同一事务；
9. 空 v1 Up/Down、data-bearing v1 upgrade fail closed、v2 reopen、migration drift；
10. 所有 a0 测试继续通过，且 secure core 没有 HTTP listener、private key、平台 DB 或

dependency lock、Contract Manifest/Suite、projection manifest、v2 migration、public-key
test fingerprints、验证命令和完整日志。证据生成器必须动态读取 locked
`runtime-core-v1` 全部 17 个 case ID，为每个 case 输出当前 `passed/subset/blocked/not_in_slice`
及边界，禁止用固定 case 列表假装 Suite 未变化，也不得声明 aggregate profile completion。

2. a1.1.1：`migrate`/`serve` CLI、immutable environment/file configuration、

3. a1.1.2：Start route、严格 Content-Type/Content-Length/body framing、pre-parse 413、

4. a1.1.3：Command route、真实 subprocess commit 前后/响应丢失/kill -9、过期 lease、

HTTP/TLS 测试矩阵至少包含：无 client cert、未知 CA、过期证书、错误 EKU、合法但未映射
caller、token subject 不匹配、TLS 版本/密码套件下限、wrong/missing Content-Type、chunked
或 Content-Length framing 歧义、超限 body 在 JSON parser 前 413、响应 body/content-type
上限、SIGTERM drain deadline、kill -9 后重开与 accepted mutation 不重复。

## 崩溃点、回滚和停止条件

关键崩溃点按顺序注入：原始 body 接收中、JSON/Schema/JWS 后但事务前、JTI 插入后但
事务提交前、Start/Command/Event 写入后但 commit 前、commit 后 response 前、work lease
取得后、checkpoint object rename 后但 manifest commit 前、SIGTERM drain 中。验收要求
rollback 不留下消费但无事实的 JTI，不重复 Run/Command/Event，不把 cancel_requested
提升为 cancelled，并保留 a0 的 lease/checkpoint 恢复不变量。

代码回滚可以移除未接线的 admission/HTTP 组件；data-bearing v2 store 不做 destructive
Down，只能继续使用读兼容的旧 binary（若已有证据）或前向修复。测试 CA/private keys
是临时资源，证据只保留非秘密 fingerprint。生产启用、密钥轮换、吊销、backup/DR、
容量、升级与多区域策略仍需独立评审。

以下任一情况停止受影响工作：锁定输入变化；Contract Schema/语义无法从呈现事实闭合；
OpenAPI 状态映射无权威答案；需要平台权威回填；需要新依赖或生产密钥；或测试只能用
mock 代替所声明的 TLS/process/SQLite crash 行为。

## 明确排除和未证明边界

a1 全程不得新增或声称：

- Go AgentRuntimeProvider adapter（属于 a2）；
- 生产 composition root、endpoint registration、container 或部署；
- token issuer、private signing-key custody、生产 rotation/revocation；
- ProviderResolution、生产 mTLS/workload identity authority；
- 平台 PostgreSQL/Temporal caller、Runtime Start Outbox 或 Workflow 改动；
- 完整 RunManifest、RootBinding、RuntimeAuthorization/ArtifactGrant lineage 权威；
- CanonicalEvent、Provider Event Inbox/projection；
- 生产 Safety Controller、SystemSafetyControl 触发/派发/终态权威；
- cross-revision checkpoint compatibility/portability；
- 完整 17-case `runtime-core-v1`、Phase 0B、端到端、可靠性、freeze、安全审批或
  production readiness。

a1.0 的完成标准是安全准入核心及其组件证据全部通过；a1.1 的完成标准是 mTLS 真实进程
边界及其组件证据全部通过。两者都只能证明“呈现请求、token 与 Provider-local durable
事实的一致性”，不能证明上游生产事实的真实性或权威来源。
