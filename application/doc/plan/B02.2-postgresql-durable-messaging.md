# B02.2 PostgreSQL Durable Messaging Implementation Plan

Date: 2026-07-23

Status: implemented and locally validated, awaiting user review. This document
governs only the B02.2 component slice; it
does not claim Phase 0B, end-to-end integration, reliability approval, formal
freeze, or production readiness.

## Authority And Locked Inputs

The locked Blueprint owns reliability semantics, PostgreSQL invariants,
technology selection, Application boundaries, engineering standards, and Phase
0 sequencing. The locked Contract owns CanonicalEvent, Event Registry,
idempotency, source identity, semantic constraints, and fixtures. Application
consumes those sources through `dependency-lock.json`; this plan records no
copied Wire schema or event registry.

B02.2 reuses the B02.1 pgx, goose, sqlc, Staticcheck, PostgreSQL image, role,
TenantContext, and real-database harness pins. It introduces no Broker, Redis,
OCI image, or third-party library.

## Scope

- SQL-first PostgreSQL Outbox and Transport Inbox tables with explicit
  `tenant_id`, constraints, indexes, enabled and forced RLS, and exact
  Application Role ACLs.
- A globally unique Transport Message ID shared by Outbox delivery and the
  Inbox `(consumer, message_id)` identity. Cross-Tenant reuse fails before
  dispatch without exposing the existing Tenant row.
- Transaction-scoped Outbox enqueue in the existing Tenant transaction, with an
  Application-private encoded payload ceiling and exact byte digest. Large
  payloads remain content-addressed references rather than durable queue bytes.
- Bounded `FOR UPDATE SKIP LOCKED` claims with lease expiry, monotonically
  increasing fencing tokens, retry scheduling, live-lease renewal, success
  acknowledgement, retryable failure, and terminal failure. PostgreSQL owns the
  operation time; Workers submit only bounded durations.
- Atomic Inbox consumption keyed by `(consumer, message_id)`: identical digest
  replay skips the side effect and a digest conflict fails closed.
- Domain-valued messaging APIs and a dispatcher service that perform transport
  I/O only after the claim transaction commits.
- Real PostgreSQL, concurrency, race, RLS, privilege, migration, recovery, and
  transaction-atomicity evidence bound to the locked sources and tool pins.

## Contract Boundary

The locked Contract defines the source identity tuple and Dedupe Key algorithm,
but its string schemas allow escaped `U+0000`. PostgreSQL `text`/`varchar`
cannot represent that value, and the locked Contract does not define a narrower
database-safe identifier profile. Per the Application boundary, this slice does
not tighten the Wire Contract or invent an encoding. Canonical source Inbox is
therefore blocked and omitted from B02.2 until a reviewed Contract revision
closes that representation gap.

The Contract also does not define one universal encoded-byte limit for a
complete CanonicalEvent transport envelope. The durable-message byte limit is
an internal storage guard, not a new Wire limit.

## Outbox State And Fencing

The row state is `pending`, `leased`, `succeeded`, or `terminal_failed`.
`pending` becomes claimable at `next_attempt_at`. A claim transaction locks a
bounded ordered set with `FOR UPDATE SKIP LOCKED`, increments the fencing token,
increments the attempt count, and records Worker and lease expiry. An expired
lease can be reclaimed as a new token. Renew, acknowledge, and both failure
paths require the same Tenant, message, Worker, token, state, and unexpired
lease. PostgreSQL evaluates one authoritative operation timestamp inside each
transaction; a Worker cannot supply an absolute lease timestamp. Lease duration
is bounded to five minutes and retry delay to 24 hours; both must be represented
exactly at PostgreSQL's microsecond precision rather than silently truncated. A
stale or expired owner cannot complete a newer claim.

The dispatcher starts a lease-shorter attempt deadline before renewing each
claimed row, then gives transport only the remaining budget. This accounts for
the renewal transaction and network latency rather than starting a fresh timeout
after renewal. If renewal is lost or consumes the budget, that row is not sent.
A transport that ignores context cancellation can still produce an at-least-once
duplicate, so Inbox idempotency remains mandatory.

Retryable failure clears lease ownership and returns the row to `pending` with a
database-timed `next_attempt_at`. Terminal failure and success clear the lease
and retain bounded reconciliation metadata. Delivery remains at least once; an external
side effect may succeed before a lost acknowledgement, so consumers still need
Inbox idempotency.

## Inbox Atomicity

Inbox acquisition, the caller-supplied PostgreSQL side effect, and completion
are one Tenant transaction. A new message runs the effect once. An identical
transport replay returns the stored completion without rerunning the effect.
Reuse with a different payload digest fails closed. A failed effect rolls back
both the Inbox row and the effect so a later retry can execute.

## Migration And Rollback

The migration is an expand-only addition with no rewrite of B02.1 rows. Its Down
is safe only while all B02.2 tables are empty; otherwise it raises a forward-only
error and leaves both schema and goose version intact. After committed messaging
data exists, recovery is a reviewed forward migration. Tool or dependency
rollback restores the previously admitted exact pin and regenerated sqlc tree,
then reruns the full real-PostgreSQL Gate. PostgreSQL data directories are never
downgraded in place.

## Review Remediation

The first 2026-07-24 review found four issues. The implementation now uses
PostgreSQL-authoritative lease time and bounded durations, renews before every
bounded transport attempt, applies the same character-counting Message ID rule
to write and status paths, and verifies FORCE RLS plus cross-Tenant denial after
a refused data-bearing Down. A second review removed interval precision
truncation, made the attempt budget include renewal latency, treated a changed
Outbox `created_at` as an identity conflict, and replaced broad durable-table
DML grants with exact column ACLs. Targeted unit tests and the repeated real
PostgreSQL Race harness pass, followed by the complete Application Gate.

The third review found an unclosed cross-Tenant Transport Message ID namespace,
a real Contract/PostgreSQL NUL representation gap, unbounded Dedupe Key error
echoing, and unrestricted failure-kind strings. Remediation makes Transport
Message IDs globally unique before dispatch, withdraws the blocked Canonical
source sub-scope and traceability claim, and constrains failure kinds in both Go
and PostgreSQL. The complete Application and Contract Gates passed after these
changes.

The fourth review found that Renew/Ack/Fail materialized database time before a
possible row-lock wait, so a wait crossing lease expiry could retain the stale
pre-wait timestamp. Lease mutations now lock the exact Tenant/Message/Worker/
Fencing row before reading `clock_timestamp()`. A real PostgreSQL regression
holds that row lock, expires the lease, releases it, and proves the waiting Ack
is rejected without changing state. The same review fixed Dispatcher Tenant
validation before Store access, escaped caller-controlled IDs in errors, fixed
ASCII/hex database checks to `C` collation, constrained live lease expiry after
`updated_at`, and replaced a date-sensitive 24-hour test fixture with a stable
far-future value. The repeated PostgreSQL Race harness and complete Gates pass
after remediation.
