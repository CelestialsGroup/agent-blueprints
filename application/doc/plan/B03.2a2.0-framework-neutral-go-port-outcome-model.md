## 下一切片判断与 a2 拆分

权威和当前代码审计表明，B03.2a1.1.4 已闭合法定 Status/Event read 与 Provider-local a1.1
evidence，但 `internal/runtimeport` 仍只有 Contract projection 与指导性 README，不存在 Go Port、
HTTP adapter 或跨语言 evidence。原 B03.2a2 同时包含 Port、HTTP、真实进程集成、reconciliation
和 Suite evidence，不能作为一个最小独立切片一次实现。

因此 B03.2a2 按依赖顺序拆成：

1. `B03.2a2.0 Framework-Neutral Go Port And Outcome Model`：只定义稳定 Platform-facing
   Port 值、封闭 failure/outcome 与 reconciliation requirement；
2. `B03.2a2.1 Strict Unwired HTTP Adapter`：只由 component/integration harness 构造的严格
   HTTP adapter，不做生产注册；
3. `B03.2a2.2 Installed Native Runtime Cross-Language Component Evidence`：使用真实安装 wheel、
   mTLS、HTTP、SQLite 和 Go adapter 的跨语言进程证据；
4. `B03.2a2.3 Dynamic Suite Evidence Closure`：动态读取锁定 Suite，绑定前述分层 evidence，
   保持 aggregate 与平台依赖 case 不提升。

本轮只实施 a2.0。它不依赖生产 endpoint/TLS authority、ProviderResolution、token issuer/
private-key custody、平台 caller/父事实、生产 composition、CanonicalEvent、Safety Controller 或
B03.2b PostgreSQL/Temporal ownership，因此能够独立闭合。若稳定 Port 模型无法在不伪造上述
authority 的条件下成立，则停止代码范围；不得以 HTTP adapter、测试替身或本地 shadow authority
绕过。

## Scope

本切片只实现和证明：

- framework-neutral `AgentRuntimeProvider` Go Port，覆盖 Capabilities、Start、Status、Command、
  Events 操作，但不包含 transport 或构造实现；
- 不泄漏 generated DTO、`net/http`、Provider-private checkpoint content 或 Native Runtime 私有 ID
  的稳定请求/响应值；
- 操作名、failure class、mutation disposition 和 reconciliation read operation 使用封闭、稳定、
  可验证的值集合；
- mutation disposition 精确区分 `accepted`、`rejected`、`not_dispatched`、
  `outcome_unknown`，并以构造期 invariant 拒绝非法组合；
- `outcome_unknown` 必须携带对账要求，明确原 mutation 不可重放、必须取得新的 Status/Event
  authority，并保留原 operation/request identity；
- `accepted`/`rejected` 只表达 Provider 调用结果，不把 Cancel acceptance 解释为 terminal
  cancellation，也不生成平台父事实；
- mutation Port 不暴露 retry count、retry policy 或自动重试方法；
- 敏感 token 与 Contract document 使用有界、不可变、防御性复制的 opaque value，
  `String`/`GoString` 固定脱敏；其存在不声明 JWS、Schema、semantic 或 HTTP validation；
- focused Go normal/Race tests、动态 evidence、source manifest、敏感扫描和完整 Application Gate。

## Non-Goals

本切片不实现或不声明：

- HTTP client/adapter、URL/Host、TLS 配置、redirect、deadline、response reader 或状态码映射；
- 真实 Native Runtime 进程、跨语言、mTLS、HTTP、SQLite 或网络行为；
- Status/Event malformed request 的 HTTP 400 解释；锁定 OpenAPI 缺口继续 blocked；
- ProviderResolution、Provider/Revision/PortBinding persistence 或生产 endpoint/TLS authority；
- token issuer、签名、private-key custody、rotation/revocation 或生产 workload identity；
- 平台 caller、InvocationAttempt、ReconciliationCase、RuntimeAuthorization、RunManifest、
  RuntimeRun、CanonicalEvent 或生产 PostgreSQL/Temporal ownership；
- production `cmd/`、container、Worker、Outbox dispatcher、Safety Controller 或 composition root；
- checkpoint content/restore、CanonicalEvent projection、SystemSafetyControl dispatch；
- aggregate `runtime-core-v1`、Phase 0B、端到端、0H reliability、freeze、安全审批或
  production readiness。

## 全阶段不变量

1. Blueprint/Contract zero-diff；不得修改上游权威迁就实现。
2. 只使用 Go 标准库和现有 module dependency；不新增或升级依赖。
3. 根 `runtimeport` package 不得导入 generated runtime API、`net/http`、Temporal、pgx/sqlc，
   不得反向依赖 adapter 或生产 package。
4. Port 值不得使用 `map[string]any`、导出可变 slice/map 或 transport status code 作为 domain
   outcome；任何 bytes getter 必须返回防御性副本。
5. opaque token/document 必须有显式非零 byte bound，构造时复制输入并固定脱敏；错误、日志和
   evidence 不得包含 token、body、checkpoint content、private key、traceback 或内部异常。
6. Start/Command 调用只有一次 dispatch 语义；Port 不提供内部 retry 配置、方法或 callback。
7. `outcome_unknown` 不得含 success value 或 known rejection；必须含对账操作、原 mutation identity
   和 `fresh_read_authority_required=true`，且不得声明已持久化或执行。
8. `not_dispatched` 不等于 Provider rejection；`accepted` 不等于 terminal operation success。
9. a2.0 tests 只证明 Go value/Port compile-time shape 与 invariant，不用 fake HTTP/process 提升
   成熟度。
10. 每阶段先回填本计划台账，再向总控任务发送报告；不暂存、不提交、不推送。

## Rollback、Data Retention 与 Forward-Only 边界

- a2.0 只新增 Go package source/tests、evidence generator/Gate block 和文档；无 migration、网络、
  进程或 durable write，可整体移除这些未提交变更回滚。
- 本切片不创建或修改 Provider-local SQLite、Platform PostgreSQL、Temporal History、Event、work、
  checkpoint、JTI、InvocationAttempt 或 ReconciliationCase；不得为测试写入或删除真实 durable
  facts。
- opaque token/document 只存在于进程内存和测试临时值，不持久化；测试结束不保留 token/body。
- ignored build/evidence 可重新生成或移除，但删除 artifact 不是 durable data rollback；任何
  再生成都必须重新绑定完整 source/log digest。
- 当前 SQLite v2、Event retention、checkpoint 引用和 PostgreSQL/Temporal facts 的 forward-only
  规则保持不变；a2.0 回滚不得触碰、降级或伪造恢复这些事实。
- 后续 a2.1-a2.3 必须单独计划其 transport、process 和 evidence rollback；本计划不预授权。
